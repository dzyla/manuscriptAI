# A2a — DOCX Reader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open a collaborator's `.docx` as the manuscript — its styles, fonts, page setup, headings, nested lists, tables with merged cells, images (including text-wrapped figures) and page breaks intact, everything else preserved verbatim — and tell the author exactly what came in.

**Architecture:** Three foundation tasks first: split the pure document schema from its React node views so conversion can run in a Web Worker; load the stored document into the editor as JSON instead of via HTML; and keep Word paragraph identity on the copy that is actually untouched. Then a pure reader in `src/docx/read/` turns package bytes into `{ doc, format, assets, preservation, report }`, running in a Comlink worker. Nothing is written to the database until the author confirms the import report.

**Tech Stack:** TypeScript 5.8, JSZip 3.10, `@xmldom/xmldom` 0.8.15, Comlink 4.4, TipTap 3.21, Dexie 4, Vitest 2.

**Spec:** `docs/superpowers/specs/2026-10-07-document-engine-design.md` — §1 (fidelity contract), §2.4 (preservation), §2.6 (import transaction), §2.7 (security), §3 (core interop). Read §1, §2.4, §2.6, §2.7 and §3 before any task.

**Follows:** A1 (merged, commit `f53e74c`). A1's primitives are in place: `src/extensions/schema.ts`, `src/docx/preserve/*`, `src/docx/fidelity.ts`, `src/db/assetStore.ts`, `src/db/documentRepository.ts`, Dexie v3.

**Followed by:** A2b (writer + Word interoperability harness). A2a must therefore produce preservation data complete enough to write the package back, even though nothing writes it yet.

## Global Constraints

- Guiding principle: **editing a supported part of a collaborator's Word document must not damage unrelated content, metadata, citations or revision history.** Prefer preserving over approximating; anything not understood becomes an opaque atom, never silent loss.
- Fidelity categories come from spec §1 and `src/docx/fidelity.ts`. Every element the reader handles must `recordFeature` under its spec category; category 4 must warn.
- All XML uses `@xmldom/xmldom` (`DOMParser`, `XMLSerializer`) — never `window.DOMParser`. All of `src/docx/**` must stay free of React, DOM globals and `@tiptap/react` so it can run in a Web Worker.
- Binary data is `ArrayBuffer`, never `Blob`.
- The reader is **pure**: `.docx` bytes → `ImportResult`, no IndexedDB writes, no store mutations. Only `documentRepository.importDocx` commits, after the author confirms (spec §2.6).
- Security limits (spec §2.7), enforced from the zip central directory **before** inflating: reject `.docm`/`.dotm` or any package containing `vbaProject.bin`; compressed ≤ 50 MB; total uncompressed ≤ 300 MB; ≤ 2000 entries; per-entry compression ratio ≤ 100:1; reject absolute paths and `..` segments; never fetch `TargetMode="External"` relationships; only `http`, `https`, `mailto` hyperlinks become clickable.
- Google Docs exports are a first-class input: `w:sdt` wrappers tagged `goog_rdk_*` are transparent and must be unwrapped (category 1), and embedded fonts under `word/fonts/` stay in the package.
- Type-check gate: `npx tsc --noEmit` (do **not** use `npm run lint`: an rtk proxy distorts its output). Test gate: `npx vitest run`. After any `npm run build`, run `git checkout -- dist-electron` — the build rewrites those tracked files.
- Baseline at plan start: `tsc` clean, 179 tests passing.
- Never commit the user's grant text or any real `.docx`. Private calibration documents live in gitignored `fixtures/private/`. Committed fixtures are generated by `scripts/fixtures/make-docx-fixtures.ts`.
- Work in the worktree `.worktrees/feat-a2-docx-interop` on branch `feat/a2-docx-interop`.
- Commit after each task; messages end with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Review Focus

1. A malicious or corrupt package (zip bomb, path traversal, macro-enabled, truncated XML) must fail safely with the current document untouched, never exhaust memory → Task 4 pins each case.
2. A `.docx` whose body the reader only partly understands must still open, with every unhandled element preserved as an opaque atom and counted in the report — silent omission is the failure mode this phase exists to prevent → Tasks 5–10 each assert "unknown child → opaque, nothing dropped".
3. An image whose relationship target is missing, external, or an unsupported format must not break the import or produce a broken-looking document → Task 9 tests all three.
4. A table using `vMerge` continuation rows or `gridSpan` must not shift cells into the wrong columns → Task 8 tests both against a fixture with a known grid.
5. Importing must not clobber the open document before the author agrees, and must not half-commit if the transaction fails → Task 11 tests cancel-leaves-document and failure-rolls-back.

```ts
import { generateJSON, getSchema, type Extensions, type JSONContent } from '@tiptap/core';
import type { Schema } from '@tiptap/pm/model';
import StarterKit from '@tiptap/starter-kit';
import Highlight from '@tiptap/extension-highlight';
import TextAlign from '@tiptap/extension-text-align';
import { TableKit } from '@tiptap/extension-table';

import { FigureLabelSpec } from './specs/figureLabel';
import { OpaqueInline, OpaqueBlock } from './preserve/OpaqueNodes';
import { OoxmlProvenance } from './preserve/OoxmlProvenance';

/**
 * The document schema with no node views: safe to import from a Web Worker or
 * from Node. The editor's own list (src/extensions/schema.ts) extends these.
 */
export function getSpecExtensions(): Extensions {
  return [
    StarterKit.configure({ heading: { levels: [1, 2, 3] }, link: { openOnClick: false } }),
    Highlight.configure({ multicolor: true }),
    TextAlign.configure({ types: ['heading', 'paragraph'] }),
    TableKit.configure({ table: { resizable: true } }),
    ResizableImageSpec,
    CitationSpec,
    FigureLabelSpec,
    OpaqueInline,
    OpaqueBlock,
    OoxmlProvenance,
  ];
}

let schemaCache: Schema | null = null;

export function getSpecSchema(): Schema {
  if (!schemaCache) schemaCache = getSchema(getSpecExtensions());
  return schemaCache;
}

export function specNormalizeDoc(doc: JSONContent): JSONContent {
  const node = getSpecSchema().nodeFromJSON(doc);
  node.check();
  return node.toJSON() as JSONContent;
}

/** Needs a DOM (jsdom in tests); the worker path builds JSON directly instead. */
export function specHtmlToDoc(html: string): JSONContent {
  return specNormalizeDoc(generateJSON(html, getSpecExtensions()) as JSONContent);
}
```

### Task 3: Provenance survives on the untouched copy; package writes become cheap

**Files:**
- Modify: `src/extensions/preserve/OpaqueNodes.ts`, `src/db/documentRepository.ts`, `src/types.ts`
- Modify: `src/extensions/preserve/OpaqueNodes.test.ts`, `src/db/documentRepository.test.ts`

**Interfaces:**
- Produces:
  - `findDuplicateBlockIds(doc, isUntouched)` keeps provenance on the node that is genuinely untouched.
  - `DocxPackageRow` splits into immutable bytes and a mutable map: `{ documentId, original: ArrayBuffer, fileName, importedAt }` stays in `docxPackages`; the mutable `preservation: PreservationStore` moves to a new `preservationStores` table keyed by `documentId`.
  - `DocumentRepository.getPreservation()` / `savePreservation(store)`; `doSave` touches only the preservation row, and only when the referenced-fragment set actually changed.

**Why:** A1's guard keeps the first occurrence in document order, so pressing Enter at the start of an imported paragraph moves provenance to the new empty paragraph and the real text loses it. And `doSave` rewrites the whole `docxPackages` row — including the original `.docx` bytes — on every autosave, which becomes 10–50 MB every 30 seconds once Task 11 stores real packages. Eager pruning also makes undoing a deleted equation lose its XML.

Detection rules, in order:
1. If `ctx.hasRealHeadings`, return `[]`.
2. A candidate paragraph must be a single short line: ≤ 10 words, no terminal `.`/`!`/`?` (a trailing `:` is allowed), and its whole text must be covered by the paragraph (no body text following in the same paragraph).
3. Strip a leading enumerator (`A.`, `1.`, `1.1`, `I.`, `(a)`) before matching.
4. **Name match** → `confidence: 'name'`. Level: a `KNOWN_SECTIONS` top-level name is level 1; a known sub-section (Significance/Innovation/Approach under Research Strategy) is level 2; otherwise level 1.
5. **Format match** → `confidence: 'format'`, only when the paragraph is entirely bold (or entirely a larger font than the document default), is ≤ 8 words, and is followed by a non-bold paragraph. Level 2 if any name-matched level-1 heading precedes it, else level 1.
6. Never emit two candidates for the same paragraph index; never emit a candidate for a paragraph holding an opaque atom other than a comment anchor.
7. `recordFeature` each candidate and `addWarning` once with the total, so the import report says structure was inferred.

`applyHeadings` converts an accepted paragraph to `{ type: 'heading', attrs: { level, styleId: null, ooxml: <unchanged> } }`, preserving the paragraph's provenance and inline content untouched.
